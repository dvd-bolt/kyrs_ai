# PaperCraft AI Studio

PaperCraft AI Studio — Windows desktop-приложение для сборки академической работы из задания, методички, примера и исходных файлов. Целевой сценарий: пользователь задаёт тему и прикладывает материалы, после чего автопилот извлекает требования, проверяет источники, строит план, текст, таблицы и визуализации, формирует DOCX/PDF и выпускает отчёт контроля качества.

Текущая версия `0.2.0` — инженерная beta, а не готовый продукт для сдачи работы без проверки. Полный конвейер проверен автоматическими тестами с `FakeGeminiGateway`; реальные вызовы Gemini, Microsoft Word, LibreOffice и собранный Windows-инсталлятор в этом репозитории пока не прошли release-приёмку.

## Честный статус

Обозначения: **работает** — покрыто локальными автоматическими тестами; **требует интеграции** — код существует, но необходима проверка с реальной внешней системой; **запланировано** — обязательная часть продукта ещё не завершена.

| Подсистема | Статус | Что подтверждено и чего не хватает |
|---|---|---|
| Доменные модели и 4 профиля работ | ✅ Работает | Pydantic-модели и профили курсовой, статьи, отчёта по практике и школьного проекта проверены в `tests_v2` |
| Локальные проекты и восстановление состояния | ✅ Работает | SQLite/файловое хранилище, атомарные артефакты, миграция legacy-проекта и состояния run покрыты тестами |
| Импорт исходников | ✅ Работает | На тестовых файлах проверены TXT/MD, PDF, DOCX, XLSX/CSV, изображения, архивы и каталоги кода; OCR сканов отдельно не подтверждён |
| Безопасность импорта | ✅ Работает | Ограничения размера/архивов, хеширование, защита путей и отсутствие исполнения кода проверены тестами |
| URL-проверка, evidence и библиография | ✅ Работает локально | Детерминированная проверка и связывание сущностей работают; поведение на реальных сайтах и ограничениях сети требует приёмки |
| Gemini gateway | 🟡 Требует интеграции | Structured output, retry/error mapping, upload/delete и явный fake проверены через тестовые клиенты; live Gemini не проверялся |
| Полный автопилот | 🟡 Требует интеграции | Fake-E2E проходит от проекта и методички до DOCX и QA; качество и устойчивость live-генерации ещё не измерены |
| Расчёты и синтетические данные | ✅ Работает | Декларативные операции, provenance, seed и проверка двойной записи покрыты тестами |
| Графики и диаграммы | ✅ Работает локально | `ChartSpec` рендерится без `exec`; диаграммы имеют локальный Pillow fallback. Matplotlib требует optional-группу `visuals` |
| DOCX | ✅ Работает | Блочный renderer, поля TOC/PAGE/SEQ, стили, таблицы, изображения, код и библиография проверены структурно |
| Пользовательские DOCX-шаблоны | ⬜ Запланировано | Импорт шаблона есть на уровне источников, но его надёжное слияние с новым renderer ещё не принято |
| Word/LibreOffice и PDF | 🟡 Требует интеграции | Адаптеры реализованы; реальная Word COM/LibreOffice-конвертация на целевых Windows-машинах не проверялась |
| PDF visual QA | 🟡 Требует интеграции | Детерминированные проверки и Gemini Vision stage реализованы; нужен live-прогон на многостраничных golden-документах |
| PySide6 desktop UI | 🟡 Требует интеграции | Шесть экранов и отдельный worker реализованы; необходимы ручная приёмка и GUI-тесты на Windows |
| PyInstaller/Inno Setup | 🟡 Требует интеграции | Спецификация и скрипты добавлены, но в текущем окружении PyInstaller и Inno Setup отсутствуют, поэтому бинарник не собирался |
| Подпись кода и автообновление | ⬜ Запланировано | Для публичного релиза нужны сертификат, SmartScreen-проверка и безопасный механизм обновлений |

## Поддерживаемые типы работ

- курсовая работа, включая IT и финансовый профиль;
- научная статья;
- отчёт по учебной или производственной практике;
- школьный проект.

Если для фактического утверждения не хватает источника, конвейер должен остановиться или зарегистрировать проблему, а не выдавать выдуманные данные за реальные. Синтетические наборы допустимы только при включённой опции и сохраняют seed и явное происхождение.

## Архитектура v2

```text
src/papercraft/
├── domain/             типизированные модели и состояния
├── profiles/           правила четырёх видов работ
├── application/        сценарии, стадии и возобновляемый автопилот
├── infrastructure/
│   ├── gemini/         Gemini gateway, fake и хранение ключа
│   ├── ingest/         безопасный импорт и извлечение
│   ├── research/       URL/evidence/библиография
│   ├── persistence/    SQLite и файловые артефакты
│   ├── calculations/   факты, таблицы, финансы, synthetic data
│   ├── visuals/        декларативные графики и диаграммы
│   ├── render/         DOCX и Office/PDF finalizer
│   └── qa/             детерминированные гейты и отчёты
├── worker/             фоновый процесс конвейера
└── ui/                 PySide6 desktop
```

Каталоги `core/`, `models/`, `ui/` в корне и `web_app.py` относятся к legacy-прототипу. Они оставлены для миграции и не являются архитектурой v2. Источник зависимостей v2 — `pyproject.toml`, а не старый `requirements.txt`.

## Установка для разработки

Требуется 64-битный Python 3.12. Основная целевая ОС — Windows 10/11.

```powershell
git clone https://github.com/dvd-bolt/kyrs_ai.git
cd kyrs_ai
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[desktop,visuals]"
papercraft
```

Ключ Gemini задаётся в desktop-интерфейсе через «Настроить ключ Gemini» и сохраняется посредством Windows Credential Manager. Для разработки допустима переменная окружения:

```powershell
$env:GEMINI_API_KEY = "your-key"
```

Если ключ отсутствует, production runtime не должен молча переключаться на mock. `FakeGeminiGateway` предназначен только для явных тестов.

PDF требует установленный Microsoft Word либо LibreOffice. Для максимального качества предпочтителен Word; это требование ещё должно быть подтверждено release-тестами.

## Проверки

```powershell
python -m pip install -e ".[dev,visuals]"
python -m ruff check src tests_v2
python -m mypy src\papercraft
python -m pytest -q tests_v2
```

Тесты с реальными внешними сервисами должны иметь маркер `live` и не входят в обычный CI. Office-тесты помечаются `office`.

## Windows-сборка

Скрипт создаёт изолированное окружение `.venv-build`, устанавливает группы `desktop`, `visuals`, `build`, собирает onedir-приложение и, если найден Inno Setup 6, формирует установщик:

```powershell
powershell -ExecutionPolicy Bypass -File .\packaging\build_windows.ps1
```

Только приложение, без установщика:

```powershell
powershell -ExecutionPolicy Bypass -File .\packaging\build_windows.ps1 -SkipInstaller
```

Результаты ожидаются в `dist\PaperCraftAI\` и `dist\installer\`. До ручной проверки на чистой Windows-машине эти артефакты нельзя считать релизными. Кодовая подпись скриптом пока не выполняется.

## Данные и безопасность

- Проекты по умолчанию хранятся в `%LOCALAPPDATA%\PaperCraftAI\projects`.
- API-ключ не записывается в базу проекта или QA-отчёт.
- Исходные файлы хешируются и копируются в workspace проекта.
- Сгенерированный Python-код не исполняется: расчёты и графики используют ограниченные декларативные схемы.
- Перед сдачей пользователь обязан проверить факты, цитаты, требования методички и правила учебного заведения.
