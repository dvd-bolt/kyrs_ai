# Дорожная карта PaperCraft AI Studio

Дата актуализации: 13 августа 2026 года. Документ описывает v2 в `src/papercraft`; legacy-прототип в корневых `core/`, `models/`, `ui/` не используется как доказательство готовности.

## Как читать статусы

- **Working** — поведение подтверждено локальным автоматическим тестом без внешнего сервиса.
- **Integration required** — реализация существует, но результат зависит от Gemini, Office, Windows UI, сети или окружения сборки и ещё не принят на реальной системе.
- **Planned** — необходимой release-функции пока нет либо её текущий вариант недостаточен.

Наличие класса или кнопки само по себе не означает готовность функции. Live Gemini, Microsoft Word, LibreOffice и Windows installer на текущем цикле не объявляются проверенными.

## P0 — интеграционная приёмка

Эти задачи блокируют заявление «полный автопилот работает».

1. **Live Gemini contract suite.** Проверить настроенные model IDs, structured output, загрузку/удаление файлов, grounding, image generation, 401/403/429/5xx, timeout, retry и учёт стоимости. Никакой автоматический fake fallback в production.
2. **Golden-набор из четырёх проектов.** Для курсовой, статьи, отчёта и школьного проекта подготовить методичку, пример, смешанные источники и ожидаемые структурные инварианты. Запуск должен быть повторяемым и сохранять provenance каждого проверяемого утверждения.
3. **Windows desktop smoke test.** На чистых Windows 10 и 11 проверить создание проекта, импорт файлов, настройку ключа, отдельный worker, pause/resume/retry, открытие результатов и восстановление после принудительного завершения.
4. **Office matrix.** Проверить Microsoft 365, Word 2021 и актуальный LibreOffice: обновление TOC/PAGE/SEQ, русские шрифты, перенос таблиц, подписи, PDF и отсутствие повреждений DOCX.
5. **PDF visual QA.** Прогнать документы разного объёма, альбомные таблицы, приложения, код, диаграммы и изображения; согласовать, какие visual issues являются blocker.
6. **Windows package smoke test.** Собрать PyInstaller/Inno Setup, установить без прав администратора, проверить worker-dispatch, удалить приложение и убедиться, что пользовательские проекты не удаляются.
7. **Template integration.** Реализовать и проверить безопасное применение внешнего DOCX-шаблона без разрушения секций, стилей, нумерации и связей.

### Критерий завершения P0

- Все четыре golden-проекта получают DOCX, PDF и QA report без unresolved placeholders.
- Каждое проверяемое утверждение имеет verified evidence либо конвейер останавливается.
- Все вычисляемые числа воспроизводятся из FactLedger/Dataset.
- После убийства worker продолжает с последнего успешного checkpoint.
- Ни один ключ или полный prompt с секретными данными не появляется в логах и project database.
- Installer проходит установку, запуск, обновление поверх версии и удаление на чистой VM.

## P1 — повышение качества

1. **Requirements coverage.** Расширить детерминированное сопоставление правил методички с блоками DOCX и страницами PDF; показать пользователю источник, страницу и приоритет каждого правила.
2. **OCR и сканы.** Добавить управляемый OCR-конвейер с оценкой уверенности, ручной проверкой критичных полей и запретом использовать плохо распознанные числа без подтверждения.
3. **Научные источники.** Добавить провайдеры DOI/ISBN и официальных каталогов, дедупликацию, проверку retract/доступности и snapshot метаданных.
4. **Финансовые отчёты.** Создать отраслевые наборы инвариантов, сверку межтабличных показателей и golden ledgers; синтетические данные всегда маркировать.
5. **Редактор результата.** Разрешить правки плана и блоков с точечной invalidation зависимых стадий, историей ревизий и повторным QA.
6. **GUI automation.** Добавить `pytest-qt` для основных экранов и Windows end-to-end сценарии для worker/QProcess.
7. **Наблюдаемость.** Локальный журнал стадий, понятные коды ошибок, экспорт диагностического пакета после явного согласия пользователя; без телеметрии по умолчанию.

### Критерий завершения P1

- Требования методички имеют машиночитаемый coverage report.
- Числовые и библиографические ошибки ловятся до рендера.
- Пользователь может исправить одну секцию без полной повторной генерации.
- Регрессии UI, DOCX и PDF воспроизводятся автоматическими fixtures.

## Тестовая стратегия

Обычный CI запускается без секретов и внешних программ:

```text
ruff → mypy → tests_v2 с FakeGeminiGateway
```

Отдельные контуры не должны смешиваться с обычным CI:

| Контур | Среда | Секреты | Частота |
|---|---|---|---|
| `live` | защищённый runner | Gemini API key | вручную и перед release candidate |
| `office` | Windows VM с Word/LibreOffice | нет | перед каждым release candidate |
| `desktop` | Windows VM | тестовый Credential Manager | nightly/release |
| installer | чистые Windows snapshots | signing key только в release job | release candidate |

Live-тест не должен отправлять пользовательские документы: используются специально подготовленные обезличенные fixtures.

## Технический долг legacy

До удаления legacy-кода необходимо сохранить read-only импорт `.courseproject` и fixtures миграции. После завершения P0 старые `core/`, `models/`, корневой `ui/`, `web_app.py`, `main.py` и `requirements.txt` следует удалить отдельным изменением, когда новый desktop подтвердит функциональный паритет. Старый `ScriptExecutor` нельзя подключать к v2: графики v2 строятся только из декларативного `ChartSpec`.
